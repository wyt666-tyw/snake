# 贪吃蛇 Snake

一个基于 HTML5 Canvas 的经典贪吃蛇网页小游戏。

## 快速开始

无需安装任何依赖，直接用浏览器打开 `index.html` 即可：

```bash
# 方式一：直接双击 index.html
# 方式二：命令行打开（Windows）
start index.html
```

## 操作方式

- 方向键 ↑ ↓ ← → 或 W A S D：控制蛇的移动方向（手动模式）
- 开始 / 暂停：使用页面上的按钮（或回车开始、空格暂停）
- 点击「AI 自动模式：关 / 开」按钮可随时切换 **手动模式 / AI 自动模式**，模式选择跨局保留

## 游戏规则

- 吃到红色食物：蛇身变长一节，得分 +10
- 撞到墙壁或自己的身体：游戏结束
- 最高分通过浏览器 localStorage 本地保存，刷新页面不丢失

## AI 自动模式

AI 每一步按以下优先级决策，在**保证生存**的前提下吃食物：

1. BFS 搜索蛇头到食物的最短路径，并模拟整条路径，确认吃完后仍有足够活动空间才前往
2. 追食物不安全时，沿路径跟随自己的蛇尾绕圈，避免把自己封死
3. 仍无路时走向可达空间最大的邻格
4. 彻底无路可走才会死亡（不保证永不死亡，但死亡概率显著降低）

二. AI错误信息记录
- 错误现象：AI生成的贪吃蛇AI寻路代码出现错误，蛇经常原地来回打转，明明食物很近，却反复移动撞到自己死亡，不能连续吃到多个食物。
- 查证过程：
1. 在控制台打印蛇头候选方向和食物坐标，观察移动逻辑；
2. 发现AI只计算到食物的距离，没有判断下一步位置会不会撞到自身蛇身；
3. 查阅贪吃蛇寻路资料对比代码，确认缺少安全格子过滤逻辑，只判断距离而不判断格子是否危险。
- 修复方案：增加安全方向过滤，直接剔除撞墙、会撞到自己身体的方向，只在安全方向中挑选离食物最近的方向，解决自杀打转问题。

四.AI生成代码关键逻辑解释
1.蛇身移动原理
蛇身由一组坐标数组存储，数组首项是蛇头。每次移动，先算出蛇头的新坐标；若本次移动没有吃到食物就删除最后一位蛇尾，若吃到食物就保留蛇尾，再把新的蛇头坐标放在数组最前面，完成本次移动，从而实现吃到食物身体变长。
2.AI寻路判断逻辑
AI优先朝着食物方向前进，并且提前预判下一步目标，过滤掉超出边界和落在蛇自身上的危险位置。在所有安全方向里，挑选距离食物最近的方向，以此在尽量规避死亡的情况下，持续寻找食物。

给我写一个纯前端贪吃蛇游戏，HTML+CSS+JS，不要任何框架。
要求：键盘方向键控制蛇，吃到食物变长，撞墙/撞自己游戏结束；有计分面板，重置按钮。

结果：
基础贪吃蛇跑通，可以手动操控、计分、重置。但是代码结构较为混乱，没有预留AI接管的开关，没有本地存储最高分，界面简陋。
 
调整思路：
增加需求：预留AI/手动切换的全局开关；增加localStorage保存最高分，刷新页面最高分不丢失；整理代码结构，把蛇移动逻辑单独抽成函数，方便后面AI模块调用。
  
第2轮提示词 
在刚才的贪吃蛇代码基础上继续开发。

1. 增加【手动/AI自动】模式切换按钮，游戏运行中可以随时切换，切换时游戏不停。

2. 用localStorage记录最高分，刷新网页最高分不会清零，重置游戏只清空本局分数，最高分保留。

3. 编写AI自动决策逻辑：AI自动控制蛇移动，目标是吃到食物，优先避开墙体、蛇自身身体，不能死。
思路：每次决策，预判蛇下一步所有方向；剔除撞墙、撞到自身的方向；在剩下安全方向里，挑选距离食物最近的方向前进。

4. 纯HTML/CSS/JS，不引入外部库，代码注释清晰。
 
结果：
AI基础寻路可以吃到食物，但是存在缺陷：蛇很容易进入死胡同，吃到十几个食物之后就会把自己围死，达不到连续吃完15个食物不死的硬性指标。手动/AI切换、最高分存储功能正常。
 
调整思路：
AI策略升级，增加死路预判（前瞻几步，预判走这个方向之后会不会被自己包围）。不能只看下一步，简单贪心找食物；增加优先级：优先保证存活，其次再靠近食物。
六.论文 《Croc: Training the Next Generation Chip Designers on Domain-Specific End-to-End Open Source Silicon》跑通记录 
前端（verilator仿真）核心任务：硬件逻辑功能验证
 
1. 使用Verilog/SystemVerilog编写RISC-V SoC的硬件RTL代码，描述芯片内部寄存器、运算单元、总线等数字逻辑行为。

2. Verilator工具将硬件RTL代码编译转换成C++可执行程序，完成行为级仿真。

3. 运行示例程序（ helloworld ），在仿真环境中模拟RISC-V内核执行软件代码，观察输出打印信息。

4. 目的：只验证逻辑行为是否正确，不关心芯片物理版图。

- 检查RTL代码有没有逻辑bug；

- 确认CPU可以正常取指、执行指令，运行helloworld并输出文字；

- 输出产物：仿真日志、控制台打印结果、波形文件。
 
后端（yosys综合）：把前端验证通过的RTL逻辑，转化成硅片上可以制造的物理版图。
 
Yosys（逻辑综合 Synthesis）
 
1. 输入：前端验证完成的Verilog RTL代码。

2. 工作：把高层硬件描述，翻译成基础门电路（与门、或门、D触发器等）的连接清单，称为门级网表。
